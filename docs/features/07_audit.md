# Status audit log
An AFTER UPDATE trigger writes actor UUID, previous/new status, lead, business and timestamp in the same transaction as the status update. Identical status writes create no event; failed audit insertion rolls the status update back. Tenant-scoped SELECT and no app-role UPDATE/DELETE prevent owners from forging or erasing history. Service operations use a null actor when no Auth session exists. Legacy null-slug leads resolve only through their mapped owner. Private SECURITY DEFINER trigger is not exposed as an RPC.

Owners can read the newest 50 events, 20 qualifications, 20 reply drafts and 8 report snapshots at /dashboard/activity. Lists are explicitly bounded. Rendered model strings are escaped by React. The activity table also records qualification fallbacks and job failures. Manual lead creation uses immediate local rules; the durable job is the sole model qualifier, avoiding duplicate Gemini calls. Prepared owner emails recheck the current verified recipient before sending, so an ownership change cannot send an old snapshot to a former owner. Privileged database administrators remain able to manage retention; this is not an external tamper-evident compliance archive.

Manual setup: backup/restore-copy rehearsal and migration 07, test two-owner isolation and a deliberate audit-write failure, then approve any production application separately. No new environment variables or redirects. Estimated incremental monthly cost ₹0 at small-business volumes in the existing database; plan retention before high volume.

Rollback: revert app changes; keep audit history. Removing trigger 07 is an explicit loss of future audit coverage and must be reviewed. Disposable-staging rollback removes the trigger/function while preserving existing events; never grant owners audit write/delete permission.
