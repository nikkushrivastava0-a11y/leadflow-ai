# Razorpay test checkout and expiring test access
Adds /dashboard/billing, official Razorpay Checkout, server-confirmed success, and /dashboard/pro protected by tenant-scoped, non-revoked, unexpired test entitlement checks on every request. The server's catalogue owns price/currency/duration. Client callbacks never grant access. Existing raw-body HMAC webhook, provider capture lookup, stored-order ownership, replay ledger and refund/dispute tombstones remain authoritative. Signed failed payments are recorded privately without granting/revoking access. Closed/failed checkout displays a retry message; uncertain verification says not to pay again. Live keys are rejected.

Manual setup: backup/restore and migration 05 rehearsal; inspect whether the PR55 test ledger proposal was previously applied (migration intentionally refuses an existing ledger rather than guessing). Set LEADFLOW_BILLING_MODE=razorpay-test, RAZORPAY_KEY_ID=rzp_test_…, RAZORPAY_KEY_SECRET, separate RAZORPAY_WEBHOOK_SECRET (24+ chars), LEADFLOW_TEST_PLAN_CATALOGUE JSON (amount in paise, INR, durationDays), and LEADFLOW_TEST_CHECKOUT_UI=true. Configure the Razorpay TEST dashboard webhook at https://<approved-host>/api/billing/webhook for payment.captured, payment.failed, refund.processed and dispute events. Use only test payment instruments. Confirm automatic capture in test settings. No callback URL redirect is needed for the in-page handler; keep existing Supabase Auth redirects unchanged.

Risks: provider webhook retries, capture delay, external checkout script blocking, expired/refunded access, pre-existing schema mismatch. Offline tests cannot certify Razorpay dashboard delivery or checkout browser interaction. Test entitlements prove the access lifecycle; they do not enable live paid billing or promise a new Pro feature set. Estimated incremental monthly payment cost ₹0 for test transactions; existing hosting/database quotas apply. No real charge, subscription, paid service or live credential is enabled.

Rollback: disable LEADFLOW_TEST_CHECKOUT_UI and set LEADFLOW_BILLING_MODE=disabled, revert app commit, retain ledger for reconciliation. Do not reset event IDs or remove revocation tombstones. Destructive rollback 05 is only for disposable staging after ledger export.
